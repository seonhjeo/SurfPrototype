# 기획·개발 문서 관리 안내

## 관리 방법

- 문서를 작성하거나 수정하기 전에 [기획·개발 문서 관리 지침](../AgentDocs/Documentation.md)을 확인한다.
- 각 폴더에서 플레이어, 맵 등 파트별로 문서를 나누고, 해당 폴더의 `index.md`에 연결한다.
- `기획서/`에 전체 기획을 유지하고, `개발문서/`에서 개발단위별 구현 내용과 완료 체크 상태를 관리한다.
- 각 개발단위 설명 끝에 `- [ ] 개발 완료`를 두고, 개발이 완료되면 `- [x] 개발 완료`로 변경한다.
- 기획서를 추가·수정·삭제할 때마다 대응하는 개발문서 또는 개발단위도 함께 추가·수정·삭제한다.
- 체크된 개발단위가 수정되면 다시 미체크로 변경한다. 변경되지 않은 개발단위의 체크 상태는 유지한다.
- 문서 추가·이동·이름 변경·삭제 시 관련 인덱스와 기획서 연결 링크도 함께 갱신한다.
- 모호한 내용이 있으면 개발 전에 사용자에게 질문한다. 브랜치·병합 절차는 [Git·테스트 지침](../AgentDocs/GitAndTesting.md)을 따른다.
- 이 지침 문서는 빈 줄을 포함해 100줄 이내로 유지한다.

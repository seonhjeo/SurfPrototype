## 저장 모델과 데이터 검증

- 기획: [저장 범위](../기획서/로컬설정프리셋.md#저장-범위--2026-10-01-확정), [검증과 오류 처리](../기획서/로컬설정프리셋.md#검증과-오류-처리).
- `src/match-presets.ts`에서 전용 localStorage 키와 최신 version 2 문서, ID·이름·ISO UTC 생성/수정 시각·원본 settingsVersion/settings 목록을 관리한다. 기존 version 1 항목은 settingsVersion 1로 해석한다.
- 읽기·불러오기·가져오기는 [설정 버전 변환](#설정-버전-변환과-구조-변경)을 거쳐 현재 설정 복사본을 반환하고, 저장·덮어쓰기는 현재 `validateMatchSettings`를 검사한다. `random`, 기본값 `null`, OFF 값, 이동 라인 및 독립 포탑 배치 수량을 보존한다.
- 불러오거나 반환하는 설정은 복사해 원본과 편집 상태의 참조를 분리한다. 손상·잘못된 설정·미지원 버전을 적용하지 않고 안내하며 기존 데이터를 임의로 대체하지 않는다.
- 저장 목록에 잘못된 항목이 있으면 전체 조회·CRUD·내보내기를 차단하고 원본 JSON을 유지한다. 프리셋 오류가 기존 경기 설정의 직접 편집·완료를 차단하지 않게 한다.
- 검증: 새 인스턴스의 복원, 전체 설정 왕복, 반환값 수정의 원본 분리, 손상 JSON·항목 형식·잘못된 설정·미지원 버전 거부를 확인한다.
- [x] 개발 완료

## 프리셋 저장·수정·삭제

- 기획: [저장·관리와 경기 적용](../기획서/로컬설정프리셋.md#저장관리와-경기-적용), [검증과 오류 처리](../기획서/로컬설정프리셋.md#검증과-오류-처리).
- 목록 조회·새 저장·설정 덮어쓰기·이름 변경·삭제를 구현한다. 이름은 trim 후 1~40자로 검증하며 중복 이름은 거부한다. 덮어쓰기와 삭제는 확인을 거친다.
- 저장 목록은 최대 100개로 제한하며 한도를 넘는 새 저장은 기존 목록을 보존하고 거부한다.
- 저장·덮어쓰기 전에 화면 입력과 최종 스키마를 검증한다. 성공한 관리 작업은 즉시 영구 저장하며 팝업 취소와 구분한다.
- 새 저장·명시적 덮어쓰기는 대상 항목만 현재 설정 버전/전체 스냅샷으로 기록한다. 표시 이름 변경·삭제·다른 항목의 변경은 나머지 원본 settings/version을 보존하며 명시적 쓰기의 문서 형식은 version 2다. 읽기·불러오기·팝업 취소·경기 설정 완료는 프리셋 저장소를 자동 갱신하지 않는다.
- 저장소 접근 차단·용량 부족·쓰기 실패는 오류로 알리고 이전 목록 및 현재 편집을 보존한다. 성공한 경우에만 목록과 성공 안내를 갱신한다.
- 검증: CRUD, 이름 공백·중복·길이, 덮어쓰기/삭제 확인 취소, 저장 실패의 데이터 보존과 성공 오표시 없음을 확인한다.
- [x] 개발 완료

## JSON 파일 가져오기·내보내기

- 기획: [JSON 가져오기·내보내기](../기획서/로컬설정프리셋.md#json-가져오기내보내기--2026-10-01-확정).
- 저장된 선택 항목 하나 또는 전체 목록을 version 2/presets 문서로 내보내며 각 항목의 원본 settingsVersion/settings를 유지한다. 내보내기는 저장소를 쓰지 않는다. 변환한 편집본을 내보내려면 명시적으로 저장·덮어쓴다.
- 파일의 버전·전체 항목 형식·이름·설정을 모두 검증한 뒤 한 번에 추가한다. 검증 또는 저장 실패 시 일부 항목만 추가하지 않으며 현재 경기 편집본도 유지한다.
- version 1 파일은 과거 설정 구조 1로, version 2 파일은 항목별 settingsVersion으로 검증·변환한다. 가져오기는 새 ID/시각/충돌 이름을 부여하되 가져온 원본 settings/version과 기존 나머지 항목의 원본을 보존한다.
- 실제 JSON 파일은 최대 1 MiB로 제한하고 가져오기 후 합계가 100개를 넘으면 파일 전체를 거부한다. 한도 오류에도 기존 데이터를 보존한다.
- 가져온 항목은 모두 새 ID와 현재 생성/수정 시각을 사용한다. 이름이 겹치면 기존 항목을 유지하고 최초로 사용 가능한 ` (2)` 이후 번호를 붙이며 40자 제한을 지킨다. 파일 내부 중복과 반복 가져오기도 같은 규칙으로 처리한다.
- 검증: 선택/전체 내보내기 왕복, 서로 다른 저장소로 이동, 동명이름·파일 내부 중복·반복 가져오기, 긴 이름의 번호 공간, 잘못된 항목/버전/JSON·크기/합계 한도와 쓰기 실패의 원자성을 확인한다.
- [x] 개발 완료

## 설정 버전 변환과 구조 변경

- 기획: [설정 버전 변환과 원본 보존](../기획서/로컬설정프리셋.md#설정-버전-변환과-원본-보존--2026-10-01-확정).
- `src/match-presets-schema-v1.ts`에 과거 설정 구조·범위·맵/날씨 목록을 고정한 독립 검증기를 보존한다. 현재 경기의 `validateMatchSettings`가 바뀌어도 과거 규칙을 자동으로 바꾸지 않는다.
- `src/match-presets-migrations.ts`는 source 버전의 엄격 검증 → 명시적 경로별 add/rename/remove → 다음 버전의 엄격 검증을 순서대로 실행한다. 원본을 복사해 변환하고 알 수 없는 버전·필드, 누락/충돌 경로와 잘못된 기존 값은 거부한다.
- add는 해당 버전에서 추가한 새 필드만 기본값으로 보완한다. rename은 원래 값을 옮기고 remove는 등록된 과거 필드만 삭제한다. 기존 필드의 오류·누락·허용되지 않은 null을 보정하는 일반 기본값 합치기는 사용하지 않는다.
- 현재 실행 코드의 설정 구조로 등록하는 버전은 1뿐이다. 실제 추가·개명·삭제 항목이 없으므로 기존 게임 설정을 유지하며 미래 버전 1→2(추가/중첩 추가)→3(이름 변경)→4(삭제)는 주입한 테스트용 구조로만 검증한다.
- 향후 경기 설정의 필드·범위·허용 맵/날씨를 바꿀 때는 새 settingsVersion과 해당 버전 검증기를 등록하고, 기존 검증기를 previousVersions에 보존한다. 연속된 버전 사이의 명시적 변환과 각 source/target·오류·원본 보존 테스트를 추가한다. 현재 기본값과 고정 과거 구조를 대조하는 검증으로 버전 등록 누락을 드러낸다.
- 검증: 기존 v1 저장소/JSON → 현재 설정 읽기와 무쓰기, 새 v2 설정 버전 표기, 덮어쓰기 대상만 최신 스냅샷 저장, rename/delete/import/export의 원본 버전 보존, 미래/알 수 없는/잘못된 형식 거부, 가상 여러 버전의 값 보존·새 기본값·rename/remove와 원본 분리를 확인한다.
- [x] 개발 완료

## 팝업 적용과 AI·비공개 경기 연결

- 기획: [저장·관리와 경기 적용](../기획서/로컬설정프리셋.md#저장관리와-경기-적용), [경기 설정 팝업](../기획서/화면구성.md#경기-설정-팝업--2026-10-01-확정).

## 로컬 설정 프리셋 구현 검증 — 2026-10-01

- 메인 에이전트의 실제 통합 검증 보고에 따라 Node.js 24.19에서 `npm test` 최종 140/140개(기존 125개·신규 프리셋 15개), `npm run typecheck`, `npm run build` 통과를 확인했다. 마지막 ID 생성 호환 수정 뒤 전체 테스트와 타입 검사 포함 빌드를 재실행해 종료 코드 0을 확인했다. 기존 번들의 500 KB 청크 경고는 남았다.
- 신규 자동 테스트는 전체 설정과 ID/생성시각 보존·CRUD·원본 분리, 이름 공백/중복/길이와 잘못된 설정 거부, 손상 JSON/버전/항목·존재하지 않는 ID·저장 접근/쓰기 오류, 다른 탭의 변경 보존을 확인한다. 선택/전체 JSON 내보내기·새 ID/시각·동명 번호·긴 유니코드 이름·파일 전체 거부·1 MiB/100개 제한·ID 생성 충돌도 확인한다. 저장소 권한·용량 실패는 주입한 저장소의 오류로 검증했다.
- LAN의 일반 HTTP처럼 `crypto`는 있지만 `randomUUID` 메서드가 없는 환경에서도 대체 ID 생성으로 저장·가져오기를 지원한다. optional 메서드 호출로 수정하고 신규 15번째 회귀 테스트에서 두 작업을 확인했다.
- 브라우저에서 숲·비·시작 20 SP를 저장한 뒤 팝업 취소·새로고침·불러오기로 복원했다. 중복 JSON 가져오기의 ` (2)` 추가, `모바일 프리셋 검증`으로 이름 변경, 시작 30 SP 덮어쓰기, 기본값 초기화 뒤 불러오기 복원을 확인했다.
- 시작 SP 51 입력은 새 저장을 막고 이름 편집기를 열지 않았다. 팝업을 취소하고 다시 열면 직전 완료값인 5 SP·맵/날씨 무작위로 복원됐다. 삭제의 돌아가기 취소와 확인 삭제도 확인했다.
- Chrome에서 선택 내보내기 `surf-preset.json`의 실제 다운로드 완료와 1,515바이트 JSON 내용을 확인하고 해당 파일을 인앱 브라우저에서 가져왔다. version 999 파일은 한국어 오류를 표시하며 목록을 보존했다. 인앱 브라우저 다운로드 이벤트 대기의 시간 초과는 Chrome의 실제 파일 다운로드로 검증을 보완했다.
- 375×667 화면에서 대화상자 폭 359px·페이지 폭 375px였고 내부 `scrollWidth`와 `clientWidth`는 모두 346px로 가로 넘침이 없었다. 키보드 Enter 저장을 확인했으며 화면 증거는 `/tmp/surf-presets-mobile.png`다.
- AI는 숲·비·시작 30 SP 프리셋으로 준비 → 실제 경기 → 약 38초 뒤 성채 자연 파괴 종료 → 재대전의 설정 유지를 확인했다.
- 비공개 PVP는 두 탭에서 같은 프리셋의 읽기 전용 설정·실제 시작 30 SP·양쪽 소환을 확인했다. 약 42초 뒤 성채 자연 파괴 종료(0:2) 후 양쪽 재대전에서 동일 설정을 확인하고 방을 정리했다. 브라우저 세 탭의 콘솔 오류·경고는 0건이었다.
- 위 근거로 신규 4개와 게임 모드/화면 구성의 변경 2개 개발단위를 완료로 갱신했다. 전체 58개 중 57개 완료이며 기존 실제 사용자 밸런스 검증은 미완료로 유지한다.
- 한국어 IME 조합 중 Enter는 코드에 방어 처리를 추가했으며 실제 IME 동작은 확인하지 않았다. 실제 기기 터치·외부 기기/네트워크·이번 변경의 공개 배포·사용자 로컬 테스트는 미확인이다. 에이전트 검증은 사용자 테스트나 `dev` 병합 요청을 대신하지 않는다.

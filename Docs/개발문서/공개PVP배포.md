# 공개 PVP 배포 개발단위

대응 기획: [로비의 비공개 방과 방 수명](../기획서/화면구성.md), [세 모드의 비공개 PVP](../기획서/게임모드.md).
Vercel 화면과 Render 단일 WebSocket 서버로 서로 다른 기기의 비공개 PVP를 제공한다. 로그인·6자리 코드·서버 전투 판정·덱 비공개·세 모드·이탈·재대전 규칙을 유지한다.
실제 서버 배포와 공개 대전 검증 전에는 아래 단위를 미체크로 유지한다.

## Render 단일 WebSocket 서버 배포

- 기획: [비공개 방과 초대 코드](../기획서/화면구성.md#로비), [방 수명](../기획서/화면구성.md#방-수명과-오류-처리--2026-09-30-확정).
- 기존 `server/start.mjs`와 `server/multiplayer.mjs`를 Node.js 24.19.0의 단일 프로세스에서 실행한다. 방과 전투 상태를 메모리에서 공유하므로 복수 인스턴스로 나누지 않는다.
- `render.yaml`을 기준으로 Singapore 지역 Free Web Service의 빌드 `npm ci && npm run build`, 시작 `npm start`, 상태 확인 `/healthz`를 구성한다. Render가 제공한 `PORT`를 사용해 `0.0.0.0`에서 접속을 받는다.
- `MULTIPLAYER_ALLOWED_ORIGINS`에 실제 Vercel 화면 출처를 지정한다. 프로토콜·호스트·필요한 포트만 포함하며 경로나 끝 슬래시는 제외한다. 여러 출처는 쉼표로 구분한다.
- `/healthz`의 정상 응답과 `/ws`의 WebSocket 연결을 확인한다. 상태 확인 응답에 방·덱·인증 정보를 넣지 않는다.
- 서버 재시작·재배포·절전 시 메모리의 방이 사라진다. 경기 중 연결 종료는 기존 이탈 규칙을 적용하며 재접속을 추가하지 않는다.
- 검증: 실제 Render 호스트·배포 커밋·Node.js 버전·빌드 및 시작 결과·상태 확인 HTTP 200·정상 WebSocket 연결을 기록한다. 로컬 실행 성공만으로 서버 배포 완료를 체크하지 않는다.
- 현재 상태: 설정·구현의 로컬 검사 완료, 실제 Render 배포와 연결 검증 대기.

## Vercel 화면 연결과 공개 대전 검증

- 기획: [세 모드와 경기 유지](../기획서/게임모드.md), [비공개 방·게임·결과](../기획서/화면구성.md).
- Vercel의 공개 빌드 환경변수 `VITE_MULTIPLAYER_URL`을 실제 Render 서버의 `wss://호스트/ws`로 지정하고 화면을 다시 배포한다. 로컬 실행은 같은 출처의 `/ws`를 사용한다.
- 실제 공개 화면 URL·서버 URL·배포 커밋·Vercel 빌드 결과와 서버 연결을 기록한다. 환경변수 입력만으로 공개 배포 완료 처리하지 않는다.
- 독립된 두 클라이언트에서 6자리 방 생성·코드 참가·방 모드 공유·덱 비공개·준비·소환·결과·이탈·재대전을 검증한다. 서로 다른 디바이스·네트워크의 확인 범위를 구분한다.
- 대기방 방장 이탈은 방 종료, 참가자 이탈은 준비·선택 타이머 초기화, 경기 중 이탈은 패배로 처리하는 기존 규칙을 확인한다.
- Render Free는 수신 HTTP 요청이나 기존 WebSocket 메시지가 15분 없으면 절전하며 다음 요청·새 연결에서 기동하는 데 약 1분이 걸릴 수 있다. [공식 절전 제한](https://render.com/docs/free#spinning-down-on-idle).
- 클라이언트는 최초 연결 전에 `/healthz`를 확인하고 최대 120초 동안 기동을 기다린다. 개별 요청 제한은 10초, 재시도 간격은 2초다. 이 대기는 최초 연결에만 적용하며 경기 재접속을 추가하지 않는다.
- PVP 화면은 좌표를 150ms 동안 보간한다. 전투 판정·SP·소환·승패는 서버 상태를 따르고 AI 대전 계산은 유지한다.
- 구현 검증: 2026-09-30 Node.js 24에서 자동 테스트 59개·타입 검사·프로덕션 빌드가 통과했다. 기존 전투·WebSocket 48개, 상태 확인과 기동 대기 4개, 화면 보간 7개를 포함한다.
- 로컬 브라우저 두 클라이언트(`http://localhost:5192`)의 생성·참가·준비·양쪽 전투·소환·상대 나가기 후 승리 화면을 확인했다. 이 기록은 실제 Render·Vercel 공개 대전 검증을 대신하지 않는다.
- 현재 상태: Render 호스트와 Vercel 환경변수 반영·공개 대전 검증 대기. 자동 검사 성공은 사용자 로컬 테스트나 `dev`·`main` 병합 요청을 대신하지 않는다.

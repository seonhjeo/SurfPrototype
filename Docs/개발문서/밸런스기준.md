# 초기 밸런스 검증 개발단위

대응 기획: [초기 밸런스 기준](../기획서/밸런스기준.md). 계산으로 확인한 수치와 실제 대전으로 확인한 결과를 구분한다.

## 수치 관리와 계산 일관성

- 기획: [수치의 성격](../기획서/밸런스기준.md#수치의-성격), [단위와 계산 초기안](../기획서/밸런스기준.md#단위와-계산-초기안).
- 사용자 지정값과 조정 가능한 초기안을 구분하고, 공통 거리 단위 U와 소수 정밀도를 사용한다.
- U는 격자가 아닌 연속 거리 단위다. 12×20 U 전장·120도 부채꼴 탐색·성채 무공격/무방어 및 피해·제어 처리는 확정 규칙이고 성채 1,000 HP는 초기안이다.
- 기획 표·게임 데이터·날씨 및 상태이상 보정에서 같은 값을 사용한다.
- 맵별 일반 수와 늪의 일반/보스 이동속도 1.3배를 동기화한다. 3분의 자기 쪽 일반 9회분·첫 보스를 모두 처치하는 조건의 총 SP는 기본 모드에서 사막 229·숲 283·늪/성 도로 247, 한정 SP 모드에서 사막 64·숲 118·늪/성 도로 82다.
- 검증: 두 모드의 시작 SP·회복량과 같은 처치 보상을 사용한 SP 계산, 맵별 수·속도, 7% 복리 계산, 표시 반올림과 실제 피해·승패 판정 분리, 공격속도와 공격 주기 환산, 사람·AI의 동일 수치를 확인한다.

## AI 상대 대전과 후반 압박 검증

- 기획: [실제 대전에서 확인할 항목](../기획서/밸런스기준.md#실제-대전에서-확인할-항목).
- 각 맵·날씨에서 사람 대 AI 1대1을 시작부터 종료까지 검증한다.
- 첫 웨이브 일반 몬스터의 1~2회 처치, 후반 웨이브의 성채 압박, 보스 대응과 권장 3분 경기 길이를 확인한다.
- 사냥꾼 반복 소환, 원거리 집결, 기사단장·대마도사 중첩 전략을 확인하고 초기안 수치를 조정한다.
- 검증: 실제 실행한 경기 조건과 결과를 기록하고 기획·개발문서를 함께 갱신한다. 산술 계산만으로 이 단위를 완료 처리하지 않는다.

## 기믹 추가 전 구현 검증 기록 — 2026-09-30

- 아래 기록은 맵별 기믹·유닛 표시 통일 변경 전 검증 결과다. 변경 후 실행한 검증은 별도로 기록한다.
- Node.js 24.19.0에서 전투 25개·WebSocket 8개, 총 33개 자동 테스트를 통과했다. 첫 소환 시 실제 전진 방향으로 부채꼴을 계산하는 회귀 테스트를 포함한다.
- 양쪽 AI, seed 23, 동일 덱(전사·궁수·사냥꾼·기사·기사단장)으로 12개 환경을 실행했다. 모두 성채 파괴로 종료했고 최소 55.40초·최대 293.83초·평균 130.14초였다. player 10승·enemy 2승으로 한 덱·한 seed의 기능 검증이며 승률 균형을 입증하지 않는다.
- 별도 테스트에서 15웨이브·세 차례 보스 경고와 생성·시간 만료·무승부·스킬 중첩을 검증했다.
- 브라우저에서 AI 대전의 실제 결과·재대전·덱 자동 채움, 독립된 두 클라이언트의 PVP·진영 표시·이탈 승패를 확인했다.
- 모바일 390×844·375×667, 가로 844×390, PC 1365×900에서 화면과 터치 소환·드래그·취소를 확인했다. 실제 휴대폰 두 대의 네트워크 접속은 사용자 테스트로 남는다.
- 권장 3분 경기 길이, 반복 전략의 강약과 실제 사용자의 조작감은 아직 확정하지 않았으므로 위 밸런스 검증 단위는 미완료로 유지한다.

## 맵 기믹·유닛 표시 변경 후 검증 — 2026-09-30

- Node.js 24.19.0에서 `npm run build`(타입 검사 포함)와 `npm test`를 통과했다. 자동 테스트는 시뮬레이션 28개·WebSocket 8개, 총 36개다.
- 맵별 중앙 좌·우/양 진영의 일반 수, 후속 웨이브 수와 7% 강화, 늪 일반/보스의 1.3배 이동 및 세 날씨·얼음 둔화 조합, 플레이어 유닛 속도와 성 도로 중립 기본 속도를 자동 검증했다.
- Chrome에서 맵 4종의 대기방·게임 기믹 설명과 첫 웨이브 전체 수 8·20·12·12, 늪 실제 이동 배율 1.3을 확인했다. 사막·숲 설명은 좌·우 각각 진영마다 적용되는 수를 명시한다.
- 아군·적군·중립 보스의 원 반지름 14px·아이콘 16px·상시 체력바 28×3px를 렌더 호출과 스크린샷으로 확인했다. 공통 금색 테두리 2px·고유 아이콘·내부색을 적용하고 전투 판정 반경은 유지했다.
- 브라우저에서 마우스 클릭·드래그 소환, 390×844 터치 탭·터치 드래그, 경기 종료 후 재대전, 844×390 가로 화면을 확인했으며 페이지 오류는 0건이었다.
- 이 검증은 구현과 입력·화면 흐름 확인이며 실제 사용자의 로컬 테스트, 경기 길이·반복 전략·조작감 확인이나 `dev` 병합을 대신하지 않는다.

## 한정 SP 모드 추가 후 구현 검증 — 2026-09-30

- 구현 담당 및 메인 에이전트의 검증 보고에 따라 타입 검사·프로덕션 빌드, 시뮬레이션 33개·멀티플레이 10개 자동 테스트(총 43개)를 통과한 결과를 확인했다.
- 브라우저에서 한정 SP 모드의 시작 20 SP와 자연 회복 없음, 마우스·키보드·드래그 소환, AI 전투의 자연 종료, 재대전의 모드 유지와 시작 SP 20 재설정을 확인했다.
- 독립된 브라우저 두 탭에서 한정 SP 비공개 방을 생성하고 기본 모드를 선택한 참가자가 코드로 입장하면 방장의 한정 SP 모드로 전환됨을 확인했다. 양쪽의 시작 SP 20과 15초 이상 자연 회복 없음·모드 표시를 확인했다.
- 기본 모드의 시작 5 SP·초당 증가를 확인하고 320×568과 데스크톱 화면에서 표시·조작 흐름을 확인했다.
- 이번 9개 개발단위는 구현 검증을 근거로 완료 처리했다. 실제 사용자 밸런스 검증과 사용자 로컬 테스트·`dev` 병합은 아직 별도 절차이며 기존 후반 압박 검증 단위는 미완료로 유지한다.

# 게임 모드 개발단위

대응 기획: [게임 모드](../기획서/게임모드.md).

## 모드 데이터와 경기 설정 유지

- 기획: [제공 모드](../기획서/게임모드.md#제공-모드--2026-09-30-확정), [선택과 경기 유지](../기획서/게임모드.md#선택과-경기-유지).
- 모드 식별자를 `standard`(기본 모드)·`limited-sp`(자동획득 금지 모드)·`no-kill-sp`(처치획득 금지 모드)로 정의하고 표시명·시작 SP·초당 회복량·`killSpRewards`를 공통 데이터에서 관리한다.
- 표시명 변경에서도 내부 모드 식별자와 전투 수치는 유지하고 로비·대기방·게임의 공통 표시명에 적용한다.
- 기본 모드는 시작 5·초당 1 SP·처치 보상 있음, 자동획득 금지 모드는 시작 20·초당 0 SP·처치 보상 있음, 처치획득 금지 모드는 시작 20·초당 1 SP·처치 보상 없음을 사용한다. 두 진영과 AI에 동일한 모드 규칙을 적용한다.
- 모드 정의를 `ModeRules`로 통합하되 기존 식별자와 `killSpRewards` 호환을 유지한다. 세 모드 모두 라인 0·미니언/성채 공격/포탑/상자 OFF다.
- AI 경기와 비공개 방 생성 시 선택 모드를 전달하고, 비공개 참가자는 방장의 모드를 공유한다. 서버 상태와 클라이언트 표시가 일치하게 한다.
- 비공개 방 생성 시 서버가 최종 rules를 room.rules로 스냅샷하고 참가·재대전에서도 유지한다. 클라이언트가 요청한 raw rules overrides는 적용하지 않는다. UI는 state.rules를 우선 표시한다.
- 대기방 → 전투 → 결과 → 재대전에서 같은 경기 모드를 유지한다. SP 최대치·소환 비용·기존 두 모드의 규칙은 유지한다.
- 검증: 세 모드의 AI 1대1, 비공개 생성·참가 및 서버 전투 상태, 두 진영의 시작 SP·회복, 처치획득 금지 모드의 전 대상 처치 보상 0, 기존 두 모드의 보상·최대치, 재대전의 모드 유지를 확인한다.
- [x] 개발 완료

## 독립 기능과 자원 설정의 부분 재정의

- 기획: [코드 기반 모드 설정](../기획서/게임모드.md#코드-기반-모드-설정--2026-09-30-확정).
- `src/game/mode-settings.ts`에서 라인 0~3·미니언·성채의 두 무기·포탑·SP 상자·시작/최대 SP·시간 보상·종류별 처치 보상을 공통 스키마로 정의한다.
- `neutralWaves.enabled`로 기존 중립 일반/보스 생성도 독립 조절하며 세 모드는 기본 true다.
- 기본 모드 정의와 부분 재정의를 깊이 병합해 경기 설정을 구성한다. 현재 로비·방·AI·재대전은 기존 세 모드 정의를 그대로 사용한다.
- 사람·AI와 양 진영은 같은 최종 설정을 사용한다. 포인터/렌더링 코드나 네트워크 서버에서 기능 수치를 중복 관리하지 않는다.
- 보상은 enabled·amount·multiplier로 종류별 조절하며 amount null은 기존 개체 정의의 reward를 사용한다. 신규 기능 초기값은 대응 기획 문서와 동기화한다.
- 검증: 기존 세 모드의 초기 SP·상한·회복·귀속·보상과 새기능 OFF 유지, 0~3라인 및 각 기능 ON/OFF 조합, 부분 설정 병합·잘못된 수치 거부와 양쪽 동일 설정을 확인한다.
- [x] 개발 완료

## 모드 설정 리팩터링 검증 — 2026-09-30

- 메인 에이전트의 실제 검증 보고에 따라 성채 공격의 유닛 전용 대상/피해 최종 수정 후 재실행한 `npm test` 95/95개(신규 코어16·통합15 포함), `npm run build`의 타입 검사·프로덕션 빌드 통과를 확인했다.
- 기존 dev와 새 구현에서 세 모드 × 네 맵 × 세 날씨의 36경기를 비교해 기존 게임 상태 필드가 매초 동일함을 확인했다. 현재 세 모드의 새 기능 OFF·라인0 플레이를 보존한다.
- 브라우저에서 기본 AI 소환, 신규3라인·미니언·포탑·상자 시각 표시, 390×844 모바일 크기에서 클릭·드래그, 결과·재대전과 콘솔 오류0을 확인했다.
- 로컬 브라우저에서 처치획득 금지 PVP의 방장/참가자 서버 설정 공유·양쪽 소환·참가자 이탈 결과를 확인했고 브라우저 오류는 없었다. AI 전용 `tests/manual/mode-preview.html?lanes=3`에서 0~3라인 설정을 미리 볼 수 있으며 PVP 항목은 숨긴다. 최종 페이지의 정상 시작과 오류 없음을 확인했고 이 페이지는 프로덕션 빌드에 포함하지 않는다.
- 위 구현 검증을 근거로 변경된 개발단위를 완료로 갱신했다. 이번 390×844 검증은 크기를 조절한 브라우저의 마우스/포인터 입력이며 실제 휴대기기의 터치 검증은 하지 않았다. 새 구현의 공개 Production 배포·사용자 로컬 테스트·실제 사용자 밸런스 검증은 아직 완료되지 않았다.

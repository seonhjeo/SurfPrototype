# 기획·개발 문서와 보고서 관리 지침

## 프로젝트 지침

- 분야별 지침은 `AgentDocs/`에 작성한다. 작성·분리·인덱싱 방법은 [루트 AGENTS.md](../AGENTS.md)를 따른다.
- 지침 문서는 빈 줄을 포함해 하나당 100줄 이내로 유지한다. `Docs/agents.md`에도 같은 제한을 적용한다.

## 기획·개발 문서 구조

- 기획 및 개발 문서는 저장소 루트의 `Docs/` 아래에 관리한다.
- [Docs/agents.md](../Docs/agents.md)에 문서 관리 안내와 각 하위 폴더의 인덱스 링크를 둔다.

| 폴더 | 내용 | 인덱스 |
| --- | --- | --- |
| `Docs/기획서/` | 온전한 기획 내용 | [index.md](../Docs/기획서/index.md) |
| `Docs/개발문서/` | 개발단위별 구현 내용과 완료 체크 상태 | [index.md](../Docs/개발문서/index.md) |

- 각 하위 폴더 안에서 플레이어, 맵 등 파트별로 문서를 분리한다. 서로 다른 파트의 내용을 한 문서에 몰아넣지 않는다.
- 각 폴더의 `index.md`에 파트와 문서 링크를 인덱싱한다. 문서 추가·이동·이름 변경·삭제 시 인덱스를 함께 갱신한다.
- `기획서/`는 전체 기획 내용을 유지하고, `개발문서/`는 이를 구현할 개발단위와 진행 상태를 관리한다.
- 개발문서와 각 개발단위에는 대응하는 기획서 또는 기획 항목의 링크를 남긴다.
- 문서가 불완전하거나 모호하면 [개발 지침](Development.md)에 따라 먼저 질문한다.
- 문서 수정의 브랜치와 push 절차는 [Git·테스트 지침](GitAndTesting.md)을 따른다.
- 지침 인덱스는 대문자 `Index.md`, `Docs/`의 파트별 문서 인덱스는 소문자 `index.md`를 사용한다.

## 개발단위별 완료 체크

- 개발문서는 개발단위별로 구분하고, 각 개발단위 설명 끝에 Markdown 체크 항목을 둔다.
- 작업 전이거나 진행 중인 단위는 `- [ ] 개발 완료`로 미체크 상태를 유지한다.
- 해당 개발단위의 개발이 완료되면 `- [x] 개발 완료`로 변경한다.
- 체크된 개발단위의 내용이 수정되면 다시 `- [ ] 개발 완료`로 변경한다. 변경되지 않은 단위의 체크 상태는 유지한다.
- 체크 상태를 바꾼 것만으로 사용자 로컬 테스트 완료나 `dev` 병합 요청이 있었다고 해석하지 않는다.

## 기획서와 개발문서 동기화

- 기획서를 추가·수정·삭제할 때마다 같은 작업에서 대응하는 개발문서 또는 개발단위도 함께 추가·수정·삭제한다.
- 기획서를 추가하면 필요한 개발문서와 개발단위를 만들고, 새 개발단위는 미체크 상태로 등록한다.
- 기획서를 수정하면 영향을 받는 개발단위의 내용도 갱신한다. 완료로 체크된 단위가 수정되면 미체크로 되돌린다.
- 기획서를 삭제하면 대응하는 개발문서 또는 개발단위를 삭제하고, 관련 인덱스와 링크도 정리한다. 다른 기획에 대응하는 개발단위는 보존한다.
- 개발단위를 직접 수정하는 경우에도 완료 체크를 미체크로 되돌리는 규칙을 적용한다.

## 보고서 및 결과물 저장 위치

- 사용자의 요청으로 생성하는 보고서, 세미나 문서 등 결과물 Markdown 파일은 기본적으로 `/Users/jeongseonho/Downloads`에 저장한다.
- 사용자가 다른 저장 위치를 명시하면 그 요청을 따른다. 프로젝트의 기획·개발 문서는 사용자가 지정한 `Docs/`에 저장한다.
- 루트 `AGENTS.md`는 지침 진입점, `README.md`는 프로젝트 실행·배포 안내로 저장소 루트에서 관리한다.
